# G3-3: an answered turn whose realized reply holds is still "answered"

From: goal G3 (understanding round 3), branch `understanding-r3`.
For: the owner of the seam in `reasoning_context.ReasoningContext.turn` and
`marco/language/realizer/` (goal W2: every hold through `realize()`).

## What happens

`ReasoningContext.turn` sets `status` from the engine's result, then replaces
`answer` with `realize(...)`. When the realizer's semantic check fails it
returns its hold sentence (`This answer is on hold.` / `답을 보류합니다.`), but
the status stays `answered`, so the UI reports `known: true` and the gate reads
an answer with no value (`unverifiable`, not `hold`).

Measured on development set v3, build half (at the start of G3.4 and at the end of round 3): one turn, a
cross-language count question (a romanized Korean name asked in English in a
Korean conversation, `How many does <name> have now?`): engine `answered`,
reply `This answer is on hold.`. Also the irregular plurals of request G3-2.

## Request

When `realize()` returns its hold for an answered result, the turn should be
a hold (status `unresolved`, meaning `act: hold` with the realizer's reason),
so a reply never claims to answer while saying nothing. The line is W2's
(`turn()` return site); G3 does not change it.
