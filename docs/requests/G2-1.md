# G2-1: an answer must name whose count it is

From: goal G2 (understanding round 2), branch `understanding-r2`.
For: the owner of `marco/language/realizer/` (W1). G2 does not own these files.

## What the goal asks

G2.4: "every answer names its subject". Round 1's one unverifiable answer on the
frozen set gave a number with no owner named.

## What happens

Every answered count question is realized by the realizer from the answered
fact. The discourse rule `meaning.json: discourse.answer_ellipsis`
(`"elide": "given_non_focus"`) elides every role the question named, so the
owner is never said:

| Language | Question | Realized answer |
| --- | --- | --- |
| English | How many caps does Hal have now? | `4 caps.` |
| Korean | 다올은 단추가 몇 개 있어? | `2개입니다.` |

`english.json` `count_have` keeps only `item` (`"keep": ["item"]`); `한국어.json`
`count_topic_copula` declares no `keep`. The engine's own sentence (styles
question render) is not used for a realized turn, so nothing in the files G2
owns can put the owner back.

Measured on development set v2 at the G2 hand-off commit (answered answerable
turns whose answer text names the asked holder, `bench/dialogue_gate.py`'s
`_mentions`): build half 8 of 101, check half 4 of 48. The ones that name it
are comparison answers (`Gil.`) and totals, which the realizer passes through.

## Request

Keep the owner in a count answer, in both languages, as a declaration:
either `answer_ellipsis` keeps the subject role of the asked fact, or each
language's count expressions list `owner` in `keep` (`english.json`
`count_have`: `"keep": ["owner", "item"]` gives `Hal has 4 caps.`;
`한국어.json` `count_topic_copula` with `"keep": ["owner"]` gives
`다올은 2개입니다.`). The semantic check already reads both roles back.

For totals and comparisons (passed through): a total's render could name its
members; G2 left it as is because count answers are the blocking share.
