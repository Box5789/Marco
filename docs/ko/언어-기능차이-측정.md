# 한국어·영어 기능 차이 측정

2026-09-18. **먼저 재고 나서 고친다.** 같은 뜻의 요청을 두 언어로 넣어
의도·대상·부정·문맥·계산을 견줬다. 새 채점기는 만들지 않았고 이미 있는 대화
경로(`ReasoningContext.turn`)와 `engine.answer` 를 그대로 썼다.

## 1. 팩 구조 — 영어에는 추론 부품이 하나도 없다

    styles/한국어.json   55,658 바이트 · 최상위 열쇠 73개
    styles/english.json   6,062 바이트 · 최상위 열쇠 25개

영어에만 있는 것은 `conversation` 하나다. 한국어에만 있는 28개 가운데 추론이
쓰는 것 전부가 들어 있다:

    관계해석(사례 48개) · 활용 · 문장분리 · 조사 · 자리조사 · 부정 · 수량표현
    자리말 · 임자조사 · 임자자리말 · 자리물음 · 지시어 · 계획 · 군말 · 출력계약
    상태표현 · 범위답 · 정정대상답 · 짧은답꼬리 · 말수식 · 조사예외 · 떼는조사 …

영어 팩이 실제로 가진 것은 관계말 25 · 질문틀 17 · 의도표 11 · 뜻표지 7 과
`conversation`(인사말 · shell 위험도 표 · 지시어 목록)이다. **대화 템플릿이지
추론 부품이 아니다.**

추론 경로가 영어 팩에서 받는 값:

    clauses {} · inflection {} · slot_particles [] · case_particles []
    negation {} · placeholders {} · quantities {}

## 2. 다섯 축 — 영어는 0/5

같은 뜻, 같은 순서의 발화. 한국어는 `민수 구슬은 8개 있다 …`, 영어는
`Minsu has 8 marbles. …` 로 짝을 맞췄다.

    축     한국어                        english
    계산   6개입니다                      None
    대상   3개입니다                      None
    부정   보류(아래 4번 참고)             None
    문맥   6개입니다 (`그것` 을 풀었다)     None
    의도   "반영했습니다" (물음 아님을 구분)  None

영어는 다섯 축 전부 `None` 이다. 까닭은 1번이다 — 읽을 부품이 없으니
`parse` 가 모든 입력에 `None` 을 돌려준다. **파일을 고를 수는 있으나 고른다고
기능이 생기지 않는다.**

## 3. 언어 선택 경로가 갈라져 있다 (그리고 설명 경로에는 안 닿는다)

    language_components._language_path   NAI_LANGUAGE -> KG_LANG -> "한국어"
    explain.py:62                        KG_LANG 만 (NAI_LANGUAGE 를 모른다)
    engine.py:108                        언어팩을 안 탄다 — 한국어 문구가 박혀 있다

실측: `NAI_LANGUAGE=english`, `KG_LANG=english`, 둘 다 준 경우 — **세 경우의
출력이 완전히 같다.**

    What is hypertension?  ->  "이 지식팩이 다루지 않는 주제입니다. …"   (한국어)
    고혈압이 뭐야           ->  "고혈압 — 고혈압(, )은 혈압이 정상 …"      (똑같음)

영어 물음에 한국어로 거절한다. 그 문구는 `engine.py:108` 의 박힌 글자다.

## 4. 재다가 찾은 한국어 결함 — 임자를 밝히면 수량 사건이 안 읽힌다

처음에는 "부정이 안 된다" 고 적었는데 **틀렸다.** 긍정문도 똑같이 막힌다.
문맥을 갖추고 다시 재니 갈리는 것은 조사 하나였다.

    민수 구슬 2개를 꺼냈다.            -> 6개입니다
    민수가 구슬 2개를 꺼냈다.           -> 보류
    민수 구슬 2개를 넣었다.            -> 10개입니다
    민수가 구슬 2개를 넣었다.           -> 보류
    민수가 지연에게 구슬 2개를 줬다.      -> 6개입니다
    구슬 2개를 꺼냈다.                -> 보류

까닭은 사례의 자리다. `꺼내`·`넣` 사례는 `['n']`·`['item','n']` 뿐이고 행위자
자리가 없다. 행위자 자리를 가진 것은 주다(`giver`·`taker`)뿐이라 주다만 된다.
**언어 기능의 구멍이 아니라 사례 덮개의 구멍이다.** 값을 틀리게 내지는 않는다 —
전부 보류다.

부정 자체는 사례가 있는 곳에서는 선다:
`하루가 지우개를 책상으로 옮기지 않았다` -> 8개입니다.

## 5. 이 측정이 보이지 않는 것

- 영어 팩에 한국어와 같은 부품을 채워 넣었을 때 **얼마나** 되는지는 안 쟀다.
  지금은 채울 것이 없어 0이라는 사실만 안다.
- `engine.answer` 의 그래프 설명 경로에서 영어가 어디까지 가는지는 거절 문구
  하나만 봤다. 영어 그래프를 넣고 재지 않았다.
- 시작 시간·메모리·팩 크기·외부 의존성은 이 문서에서 안 쟀다(목표 4번).
- 문항 수가 다섯이다. 축마다 한 짝씩이라 **경향이지 비율이 아니다.**
