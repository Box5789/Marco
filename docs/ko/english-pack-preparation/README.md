# 영어 언어팩 내용 준비

2026-09-21. 다음 메인 goal(`docs/ko/2026-09-20-language-graph-goal.md`)의 언어 그래프
전환에 쓸 **자료**를 만든 작업이다. 엔진에 연결하지 않았다.

## 이것은 무엇이 아닌가

- 영어팩 실행 성공이 아니다. 영어 입력은 지금도 전 턴 `null` 이다(`evidence/`).
- 다국어 추론 완성이 아니다. 통합·팩 교체·기억 보존 검증은 다음 goal 의 몫이다.
- 최종 런타임 스키마가 아니다. `01`~`05` 는 교환용 초안 형식이다.
- 계획서가 아니다. 규칙·뜻 대응·기존 지식 연결·평가 사례가 실제 내용으로 들어 있다.

이 자료는 개발용 AI가 작성해 제공한 것이다. MARCO 가 스스로 학습하거나 발견한
지식이 아니며, 그렇게 보고해서도 안 된다.

## 점검

```bash
python docs/ko/english-pack-preparation/check.py
```

현재 결과: 문제 0건. 고유 ID 277개, 평가 문장 111 · 학습 문장 70 · 겹침 0.

`check.py` 는 자료 안의 참조뿐 아니라 **자료가 저장소에 대해 주장하는 사실**도
대조한다 — 노드 ID 가 그 `.kg` 파일에 실제로 있는지, 출처 태그가 붙어 있는지,
공리 규칙 ID 가 `axioms/core.json` 에 있는지, 팩 집계(904/3685/752)가 지금도 맞는지.
집계가 어긋나면 실패한다. 즉 저장소가 바뀌면 이 자료가 낡았다는 것을 스스로 알린다.

## 측정한 베이스라인

진입점 `reasoning_context.ReasoningContext.turn(text, "graphs/graph_일상추론.kg")`.

- 한국어 수량 연쇄 `돌은 23개 있다 → 돌 8개를 꺼냈다 → 지금 돌은 몇 개야?`
  → `observed → observed → answered`
- 영어 동등 3턴 → `null → null → null`
- 한국어 전달 5턴 → `observed ×3 → answered ×2` / 영어 동등 4턴 → `null ×4`

영어 실패는 **해석 경로 미완성**의 증거다. 추론 연산이 영어에서 틀렸다는 증거가 아니다.
`knowledge_path` 를 주지 않으면 한국어도 `null` 이므로, 그 조건에서의 결과를
영어 실패의 근거로 쓰면 안 된다.

## 알려진 미완성

`01` 은 19개 규칙으로 13개 시나리오 중 10갈래를 직접 덮는다. 나머지 셋
(경험 개념 · 출력 전환 · 기존 KG 검색)은 전용 문법 규칙이 없고 기존 규칙과
출력·검색 층을 재사용한다 — 평가 사례는 `04` 에 있지만 문법 규칙은 없다.

`07` 의 B 표에 한국어 팩의 칸별 대응을 적었고, 그중 **미작성**으로 표시한 것:
`정정대상답` 의 영어 대응, `의도표`/`뜻표지`/`외부조사`(법령·문서 질의),
`학습질문종결`, `인코더` 설정(D9). `관계해석.context_replies` 는 한국어가 20개 이상인데
영어 초안은 5개뿐이다.

미확정 설계 결정 9건은 `06` 4절에 있다. 그중 셋은 자료만으로 정할 수 없다:
역할 키를 조사에서 역할 이름으로 올릴지(D1), `smaller` 공리를 어떻게 할지(D3),
`data/위키/정의문.jsonl` 부재 상태에서 H11 표본을 어떻게 고정할지(D7).

## 지키는 경계

- 저장소의 다른 파일은 **읽기만** 했다. 이 폴더 밖을 고치지 않았다.
- 없는 노드 ID 를 만들지 않았다. `03` 의 모든 노드 ID 는 `check.py` 가 파일에서 확인한다.
- 지식 그래프를 영어로 복제하지 않았다. 영어 표현은 **기존 한국어 노드**에 닿는다.
- `04` 의 정답 자료를 런타임 언어 자산에 넣지 않았다.
- 언어 모델·번역 API·사전학습 임베딩 의존성을 더하지 않았다.
- 기존 한국어 노드 ID 를 바꾸지 않았다. 공통 개념 ID(`c/*`)로 대응만 붙였다.
