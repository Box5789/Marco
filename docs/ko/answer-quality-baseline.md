# 답 품질 기준선 — 그래프를 골랐는지가 아니라 답이 맞았는지

2026-09-14. 얼린 잣대 열 줄 중 **답의 뜻을 채점하는 줄이 하나도 없었다.**
`안 물음 · 근거까지 봄` 도 그래프 선택이지 답이 아니다. 기준선을 만들었다.

## 규율 둘

- **라우팅 정답·그래프 경로 존재·문장 유사도는 답 정답의 대체 지표가 아니다.**
  시험이 이것을 못 박는다 — 정답 그래프를 골랐어도 결론이 틀리면 실패다.
- **개발 문항과 평가 문항을 나눈다.** 평가 문항은 고치는 데 쓰지 않는다.
  지금 개발 9 · 평가 13 이다.

## 무엇을 재나

`AppState.turn` 을 그대로 통과시킨다. 문항마다 사람이 미리 확정한다.

| 칸 | 뜻 |
|---|---|
| `답가능` | 답해야 하는가, 보류가 옳은가 |
| `필수결론.포함` / `.포함후보` | 답에 있어야 할 글자. 후보는 하나만 있으면 된다 |
| `금지결론` | 나오면 실패인 말 |
| `필요근거` | 결론을 받쳐야 할 원문 |
| `판정기준` | 단위·대상·시점 같은 조건. **자동 채점하지 않고 함께 찍어 사람이 본다** |

마지막 칸을 자동 채점하려다 한 번 틀렸다. `대상=구슬` 을 '답에 그 글자가
있어야 한다' 로 구현했더니 정답인 `"15개입니다."` 가 실패로 찍혔다.
**단위·대상·시점은 답을 해석하는 조건이지 답에 들어갈 글자가 아니다.**

## 네 축

| 축 | 보는 것 |
|---|---|
| 과제 성공 | 최종 결론이 맞았나 |
| 단정 품질 | 단정한 것 중 맞은 비율(정확률), 전체 중 단정한 비율(응답률) |
| 근거 품질 | **trace 의 근거**가 결론을 받치나. 답글에 근거를 옮겨 적은 것은 안 센다 |
| 보류 품질 | 모르는 것은 보류하고, 풀 수 있는 것을 과도하게 거절하지 않나 |

`known` 만 보고 단정으로 세면 보류가 성공으로 둔갑한다. `미지·B2·조건부족·
근거없음·A` 는 단정이 아니다. 시험으로 고정했다.

## 기준선 (2026-09-14, 커밋 `acaa918`)

`data/benchmarks/answer_quality.json` · 22문항 · 팩은 일상추론·대화예절·부당해고

```
과제 성공          18/22   81.8%
단정 정확률        10/10  100.0%
응답률             10/22   45.5%
근거 충족            3/3  100.0%
보류해야 할 때 보류    8/8  100.0%
풀 수 있는데 거절     4/14   28.6%
웹 호출 16회
```

**단정하면 안 틀린다(10/10). 대신 절반 넘게 단정을 안 한다(응답률 45.5%).**
이 기계의 성격이 숫자로 처음 나왔다. 약점은 오답이 아니라 **과잉 거절**이다.

웹 호출 16회도 기록해 둔다. 이 잣대에서는 막아 두어 I/O 가 없지만, 22문항 중
16번 웹으로 넘기려 했다는 뜻이다. 미지 정책은 아직 사용자 미정 사항이다.

## 실패 4건 — 전부 과잉 거절이고, 원인이 조합이다

```
수량-02  돌이 7개 있다 / 돌 2개를 더 넣었다 / 돌은 몇 개야?
수량-03  단추 12개에서 5개 빼고 2개 더하기 (세 턴)
수량-04  사과가 10개 있다 / 사과는 몇 개야?
지식-01  부당해고 요건 넷을 다 대고 물었을 때
```

관계 파서에 직접 넣어 좁혔다.

```
사과는 10개 있다   잡힘       사과가 10개 있다   못 잡음
돌은 7개 있다     잡힘       돌이 7개 있다     못 잡음
돌 2개를 넣었다    잡힘       돌 2개를 더 넣었다  못 잡음
```

**주격조사 `이/가` 로 쓴 진술문이 안 잡히고, 부사 `더` 하나가 막는다.**

어휘 문제가 아니다. 선언된 예시가 `구슬은 18개 있다` 처럼 `은/는` 을 쓰고,
컴파일된 틀에 그 조사가 글자로 박혀 있기 때문이다. **낱말을 몰라서가 아니라
같은 말의 다른 꼴을 못 받는 것이다.**

`상자에 구슬이 18개 있다` 가 잡히는 것은 그 꼴이 예시에 통째로 있어서다.
`이/가` 를 일반적으로 받는 것과는 다르다.

## 이 기준선이 없었으면

B·C 실패를 고쳐도 **"그래프를 더 잘 골랐다"** 까지만 알 수 있었다. 이제는
고친 뒤에 **"최종 답 성공률이 얼마나 변했고, 틀린 단정이나 불필요한 보류가
늘지 않았나"** 로 판단할 수 있다.

## 아직 아닌 것

- 22문항은 작다. 사용자 말대로 작게 시작했다. 갈래별로 더 필요하다.
- 설명·요약·비교처럼 **긴 답의 품질**은 아직 안 잰다. 핵심 명제와 잘못 덧붙인
  주장을 가르는 채점은 P7b 의 몫이다.
- 팩이 그래프 셋뿐이다. 905개 팩에서의 값은 다르다.

## 왜

미해석 문항 넷을 `답가능: 아니오` 로 뒀었다. **우리가 못 푸는 것을 답이 없는
문항으로 바꾼 것**이다. 정보는 이미 다 주어져 있고 사람은 15·21이라 답한다.
그대로 두면 `확정할 수 없습니다` 가 성공이 되고 `21개입니다` 가 실패가 된다.

넷을 답가능으로 되돌리고 보고를 두 덩어리로 갈랐다.

    [과제 해결]  정보가 충분한 문항을 실제로 풀었나
    [안전성]     이해 못 한 채 틀린 값을 단정했나 — 이 줄은 해결률과 섞지 않는다

**보류는 안전에서는 개선이고 해결에서는 미해결이다.** 한 숫자로 합치면
"못 풀어도 안전하게 보류했다" 가 "풀었다" 로 집계된다.

## 웹 호출 수를 성과로 쓰지 않는다

전부 막아도 내려가는 수다. 그리고 **문항 수가 바뀌면 견줄 수 없다.**

    같은 22문항  자리조사 전 16회 -> 후 13회      <- 이 견줌은 성립한다
    22문항 13회 -> 31문항 24회                  <- 이 견줌은 성립하지 않는다. 내가 틀렸다

앞으로 검색을 고칠 때는 **불필요한 검색이 줄었는가**와 **외부 정보가 정말
필요한 물음은 여전히 풀리는가**를 같이 낸다.

## 검색을 열어 주는 조건 — 아직 구현 전, 계약만 적는다

`부족한 것: 정답` 이라고 적으면 지금과 같아진다. 최소한 셋이 있어야 한다.

1. 무엇을 확인해야 하는가
2. 왜 대화·팩·계산으로는 안 되는가
3. 어떤 근거를 찾으면 그 빈칸이 메워지는가

검색 뒤에는 가져온 자료가 실제로 그 빈칸을 메웠는지 확인한다.


## 자동 채점은 여기서 멈춘다 — 범위를 못 박는다

숫자가 하나여도 뜻을 확신할 수 없는 답이 있다.

    15개가 아닙니다.       숫자 하나. 그런데 부정이다
    단추는 15개입니다.      숫자 하나. 그런데 딴 대상이다

규칙을 더 붙이면 채점기가 또 하나의 언어 이해기가 된다. **본체에서 풀 문제를
채점기에서 다시 푸는 꼴이다.** 그래서 넓히는 대신 **범위를 적는다.**

**자동으로 가르는 것** — 값·단위·대상이 그대로 드러난 짧은 답만.

    15개입니다.         가른다
    구슬은 15개입니다.   가른다 (대상이 물음의 대상과 같다)
    15kg입니다.         떨어뜨린다 (단위가 다르다)

**사람에게 넘기는 것** — 부정·설명·딴 대상·수가 둘 이상. 전부 `채점 미검토`.

**`채점 미검토 0` 은 모든 답의 뜻을 검증했다는 뜻이 아니다.** 지금 문항의 답이
다 짧아서 자동 범위 안에 들었다는 뜻일 뿐이다.

아직 자동인데 좁히지 않은 자리도 적어 둔다: 숫자가 아닌 필수결론(`큰 서랍`)은
여전히 글자 겹침으로 본다. `큰 서랍이 아닙니다` 를 통과시킨다. 넓히지 않기로 했으므로
지금은 고치지 않고 **한계로 남긴다.**
