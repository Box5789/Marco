# 5~7단계 지원 범위

2026-09-17 현재의 구현·실행 범위를 적는다. 이 문서는 전체 한국어 이해나 일반
지능 달성 선언이 아니다.

## 5. 지식 탐색과 추론 연결

- 내부 상태/계산이 이미 구조적으로 읽힌 뒤 전제가 부족하면 `조건부족`으로 남기며
  웹 조사를 하지 않는다.
- 읽지 못한 입력은 `입력이해실패`로 구분한다. 자가학습 그래프가 조사할 주제를
  확인하지 못하면 원문 전체를 외부 검색으로 보내지 않는다.
- 외부 사실이 필요한 질문은 최소 주제만 검색한다. 두 독립 도메인의 완결 원문이
  각각 **같은 절 안에서** 주제 뒤의 값·질문 동작·근거 동작을 언어 팩이 선언한
  관계로 함께 채우고, 추출한 값도 서로 일치해야 한다. 이 조건을 채우지 못하면
  `external_evidence_incomplete`로 남긴다. 해당 역할까지 채울 때만
  `external_evidence_found`가 된다. 원문 자체가 없으면
  `external_evidence_missing`이다.
- 언어 팩이 선언한 부정 꼴로 같은 주제·역할을 부정한 원문은 지지 근거가 아니라
  `conflicts`에 남긴다. 주제 문장과 역할 표지가 다른 문장에 흩어졌거나, 지지와
  명시 부정이 함께 있거나, 서로 다른 값을 주장하면 성공으로 합치지 않는다.
- 외부 근거는 승인 전에는 읽기 전용이며, 승인한 뒤에만 자가학습 overlay에 저장된다.
  검색 발췌·무관한 결과·출처 하나만 있는 결과는 사실로 승격하지 않는다.

지원하지 않는 것: 임의의 원인 독해·역방향 범주 추론·한국어 바꿔말하기다. 현재
팩이 선언한 원인 연결어미(`…아서/어서/와서/혀서` 등)와 `…기다렸다` 결과 구조,
그 대기 때문에 바로 나가지 않은 이유를 묻는 같은 주어의 물음만 원인이 하나일 때 읽는다.
원인 기록은 주어·결과 사건 표지를 함께
보존해, 같은 주어라도 다른 결과의 이유에 붙이지 않는다. 수영 같은 행동 사실만으로 범주 소속을
거꾸로 만들지 않는다. 이 범위를 벗어나면 입력 이해 실패로 남기며, 외부 사실 부족이나
해결 성공으로 세지 않는다.

## 6. 근거 응답과 학습 보존

- `요약`/`설명` 요청은 정확히 확인된 로컬 정의 또는 팩 안 승인 수집 기록의
  원문 문장에서 추출식으로 조립한다. 출력한 각 문장은 출처와 함께 `selected`에
  남고, 근거 밖의 원인·효과를 추가하지 않는다.
- `비교` 요청은 두 정확 표제어의 정의 또는 두 팩 수집 근거를 나란히 보인다.
  우열이나 차이를 새로 추론하지 않는다.
- 간단한 계획 요청은 언어 팩의 계획 표지가 있는 근거 문장만 번호 단계로 낸다.
  workspace/knowledge 실행 계획은 `GoalRuntime`의 등록 행동만 제시하며, 승인 전
  외부·쓰기 행동을 실행하지 않는다.
- 승인 수집 기록이 `claims`로 원인(`cause`/`effect`)·공통 속성(`attributes`)·
  선행 단계(`depends_on`)를 명시하면, 설명은 결과에서 원인까지 선언된 의존선을
  따라야 한다. 원인·결과 꼬리표만 있고 그 선이 없으면 인과 설명으로 승격하지
  않고 추출식으로 남긴다. 비교는 서로 다른 공통 속성만 선택한다.
- 계획은 `achieves`로 선언한 목표 행동과 그 선행 단계만 순서대로 고른다.
  `requires_state` 전제는 같은 대화에서 확인한 현재 상태와, 앞 단계가 `effects`로
  선언한 결과 상태로만 채운다. 결과를 만드는 후보가 여럿이거나 없으면 하나를
  지어내지 않고 계획을 보류한다. 미해석 사건·미답 빈자리가 있으면 상태 전제를
  만족했다고 가정하지 않는다. 목표·전제가 없는 이전 형식은 선언된 선행 단계만
  쓴다.
  구조가 없는 원문은 추출식 요약/병렬 비교로만 답하며 관계를 지어내지 않는다.
- 대화 상태는 대화 저장소의 `reasoning_state`에, 그래프 학습은 `.학습.jsonl`에,
  검증된 관계 표현/규칙 학습은 선택적 `models/relational.json`에 분리한다. 관계
  모델은 팩의 언어·공리를 바꾸지 못하고 사례·규칙 확장만 더할 수 있다.

지원하지 않는 것: 긴 문서의 추상적 요약, 근거가 없는 자유 계획, 원문에 없는
인과적 비교는 생성하지 않는다.

## 7. 팩·격리·비용

- 기본 pack 입력은 그래프, `.학습.jsonl`, `.수집.jsonl`, 정의 근거, 언어, 공리와
  선택적 관계 모델을 함께 보관한다. 팩 런타임은 호스트의 언어·공리·관계 모델
  파일이나 정의 자료를 대체물로 읽지 않는다.
- `AppState.export_pack()`은 현재 팩과 승인된 overlay 학습·수집 기록을 새 팩으로
  내보낸다. 대화 로그·문서·파생 색인은 내보내지 않는다.
- 교정 표현을 든 팩은 별도 Python 환경에서 호스트 `styles/`, `axioms/`, `models/`
  폴더와 `NAI_RELATIONAL_MODEL` 없이도 같은 답과 모델 근거를 재현한다.
- 비용 보고는 초기 준비, 반복 로컬 응답, Python 할당 피크, 프로세스 최대 RSS를
  따로 기록한다. 프로세스 RSS는 import와 전체 벤치를 포함하므로 단일 턴 비용으로
  해석하지 않는다. 기기 예산은 아직 정해지지 않았다.
- 대화 안에서 같은 관찰·보완 열을 다시 묻는 경우 파서와 검증된 재생 결과를
  재사용한다. 이미 해석이 끝난 대화 끝에 직접 상태 사실을 더하면 바뀐 사실만
  읽어 기존 접두어를 재사용한다. 한 문장 교정도 교정 지점 뒤가 직접 사실열이면
  그 꼬리만 다시 읽으며, 앞에 이미 확정된 정의·동작이 있어도 그대로 쓴다.
  정의·배운 동작·조건·보완 자체의 추가·교정이 그 뒤에 있으면 과거 뜻이나 이후
  상태에 닿을 수 있으므로 안전하게 전체 재생으로 되돌린다. 이 캐시는 저장·팩
  내보내기 대상이 아니며, 대화 사이에 공유하지 않는다. 각 상태 답의
  검증에는 `same_input`·`append_suffix`·`correction_suffix`·`full` 중 실제 재생
  범위도 남긴다. 전체 재생을 했더라도 교정 응답의 전이와 `affected_state`에는
  전후 값이 실제로 달라진 대상·관계만 남긴다.
- 관찰 기록 상한을 넘긴 사건은 실행 기록에 넣지 못하더라도 미해석 변화로 남긴다.
  최근 원문 보류가 다시 상한을 넘으면, 밀려난 보류는 대상·순서 단서를 가진
  안전 보류로 옮긴다. 그 안전 보류도 상한을 넘으면 가장 늦은 미확인 시점의 범용
  보류로 합쳐, 이전 값을 확정하지 않고 한도 보류를 돌려준다.
- 되물어 둔 미완성 사건이 여럿이면 행위자 하나만의 짧은 답으로 하나를 고르지
  않는다. 새 보완 문장이 이미 알려진 역할(예: 수신자)을 같은 값으로 다시 짚어
  사건을 하나로 좁히고 빈 역할도 채울 때만 그 사건에 붙인다. 다른 미완성 사건은
  그대로 남는다.
- 인코더의 방식·벡터 차원·자모 가중치·문턱·CPU 선택은 언어 자산의 `인코더`
  선언으로 팩마다 고정된다. `AppState`는 그래프 적재와 라우팅·판정을 그 팩의
  활성 인코더 범위에서 실행한다. 따라서 같은 프로세스에서 차원이 다른 두 팩을
  번갈아 열어도 각 그래프 벡터와 문턱이 섞이지 않는다.

현재 고정 로컬 대화 평가는 `reasoning_transfer_v1`에서 16/16이다. 이는 고정 개발
진단의 범위 안에서만 뜻이 있으며, 전체 한국어 독해나 일반 원인·역추론의 달성 선언은
아니다.
